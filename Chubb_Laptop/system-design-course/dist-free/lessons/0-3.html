Prerequisites Checklist

Lesson 0.3 · All levels · 5 min

This course is designed to be accessible to engineers at all levels, but there are a few things you should know before starting. Use this checklist to identify any gaps so you know what to study first.

For Everyone (Minimum Bar)

These apply whether you're on Path A, B, or C.

  • Basic programming in any language. You don't need to be an expert, but you should be able to read pseudocode and understand loops, functions, and data structures at a high level.
  • You know what a database is. You've used or heard of MySQL, PostgreSQL, MongoDB, or similar. You don't need to be a DBA.
  • You know what an API is. You've called an API from code, or at least understand that apps talk to servers via APIs.
  • You know what HTTP is. You understand that browsers and servers communicate over HTTP. You've seen URLs.

If any of these are gaps, spend a few hours on a beginner programming course or freeCodeCamp first. This course won't teach you to code — it teaches you how systems are designed.

For Pro Track (Path B)

In addition to the above:

  • You've shipped a feature to production. Even a small feature on a small team. You understand that real systems have constraints.
  • You know the difference between a relational and non-relational database. You've used one of them professionally.
  • You understand HTTP verbs. GET, POST, PUT, DELETE — you know what they're used for.
  • You've heard of caching. Redis, Memcached, or browser caching — you know caching exists and why it's used.
  • You've heard of load balancers. You don't need to know how they work internally, but you know they exist.

For Senior Track (Path C)

In addition to the above:

  • You've designed or contributed to a multi-service system. You've worked across service boundaries, dealt with network failures, or debugged production incidents.
  • You understand eventual consistency. You know what it means for a distributed system to be "eventually consistent" vs. "strongly consistent."
  • You know what a message queue is. Kafka, RabbitMQ, SQS, or any pub/sub system — you've used or debugged one.
  • You've done capacity planning. You've estimated QPS, storage needs, or bandwidth at some point in your career.
  • You're comfortable with trade-off discussions. You can defend a technical decision without saying "it's best practice."

What You Do NOT Need

Importantly, this course does NOT require:

  • A Computer Science degree
  • Knowledge of algorithms and data structures beyond the basics
  • Experience with a specific cloud provider (AWS, GCP, Azure)
  • Experience with Kubernetes, Docker, or infrastructure tooling
  • Any specific programming language

System design is about thinking clearly about constraints, trade-offs, and scale — not about knowing specific tools. The tools are examples; the thinking is the skill.
